# nyaturingtest

一个会自己混群的 QQ 聊天 bot。有人叫它、@ 它或回复它时会回；
话题对上了也会自己插一句，插了没人接就收住，不会刷屏。它也有自己的日子要过，不是一直挂在群里：
睡觉、洗澡这些手机放下的时候，叫它也不一定理。

它会慢慢记住群友：谁喜欢什么、谁和谁是什么关系、群里有哪些梗。每天凌晨，它把这些零散的印象
整理成每个人的档案和一份群志。记错了被人纠正，它会把旧说法换掉，而不是对的错的一起记着。

基于 [shadow3aaa](https://github.com/shadow3aaa/) 的
[nonebot-plugin-nyaturingtest](https://github.com/shadow3aaa/nonebot-plugin-nyaturingtest) 二次开发，
运行在 NoneBot2 + OneBot V11 上，对话模型、Embedding 和 Rerank 都通过 HTTP 接口调用，云端或本地部署的都行。

想先装起来试试，直接看[快速开始](#快速开始)。

## 聊起来是什么样

每个启用的群各自独立：有自己的人设、心情、记忆和对群友的好感，互不串门。
只有「它这个人此刻在做什么」和它的手机相册是同一个人设各群共用的，前者见下面的「它自己的日子」。

- **被叫到就回。** 叫它的名字或别名、@ 它、回复它的消息，它都会接；手机放下的时候例外，见下面的「三种状态」。
- **聊开了不会突然断。** 它说完话后 3 分钟内，刚才和它聊的人再开口，它会优先接住。
- **自己也会插话。** 群友聊得起劲、它插得上话的时候，会凑个热闹接一句。
- **冷场了会找话题。** 群里安静了两个小时以上，它会在合适的时段自己开个话题：工作日只在午饭和下班后，
  休息日白天到晚上，凌晨不打扰，一天最多两次；没人接话也不会自说自话。
- **不刷屏。** 插一句没人接就收住，不会自顾自接着说；最近的消息里它自己说的话超过两成，就不再主动插嘴；两次发言之间至少隔十几秒，一次发几条看情况，最多一张表情包。
- **看得懂图。** 每张图片和表情包一进来就会被单独看一遍，描述记在那条消息里图原本的位置；
  有人回复某张图问它，它看的就是那一张。回话时还会再看原图。同一张表情包看过一次就记住了，30 天内不会重看。
- **会点开转发。** 群友发的合并转发，它会在后台把里面的文字和图都看一遍，读完再决定接不接话；
  分享卡片能看到标题，语音、视频、文件只知道有这么一条。
- **看得到群里的 bot。** 同一个号上其他功能发的消息（查询结果、复读、推送）它都看得到，当成群里另一个人「群里的bot」，也会对它发的东西接一句。
- **知道撤回。** 有人撤回消息，它记下的那条也会变成「撤回了一条消息」，看不到原文。
- **知道群里的变动。** 有人进群、退群、被踢、被禁言，它都看得到，新人进群可能会打个招呼；也知道群名、现在多少人、上限多少。
  它自己被禁言时照常看群，只是不说话。
- **记得多久没见。** 好久没出现的人冒出来，它知道这人有几天没在群里说话了。
- **会回头接上之前的事。** 有人说过后天面试、这两天感冒了，过后它会想起来问一句；它答应过别人的事也记得，做不到会老实说忘了。问过一次就不会再追着问。
- **会发表情包。** 群友发的表情包，能拿来回应人的它会自己收藏起来（截图、照片之类的不收），所有群共用一个库，群友不常发的过几天会自动清掉；
  聊天时可以只甩一张，也可以说完话再补一张，一轮最多一张。发错了图，超级用户回复那张图发 `stickerdel` 就能删掉并拉黑。
- **会发照片。** 它有自己的手机相册：可以拍张自拍或眼前的东西，也可以翻出以前拍的旧照片，说明这是什么时候拍的。不是聊到就发，有想给人看的、或者有人想看才发。没配生图模型就没有这个功能。
- **懂 QQ 表情。** 看得懂群友发的 QQ 表情和商城表情；会给群友的消息贴表情回应，
  群里谁给谁贴了表情、一共几个人贴，它都知道，大家一起贴时也可能跟着贴。
- **会戳一戳。** 看得到群里所有人的戳一戳（拍一拍），被戳了可能戳回去、回句话或者不理，
  大家都在戳某个人时也可能跟着戳一下。
- **有心情，也记好感。** 群友的话会影响它此刻的心情（过几个小时会自己平复），也会一点点改变它对每个人的好感；两者都会反映在说话的语气上。好感度是长期养成的，不会随时间消失，只有讨厌会慢慢淡掉。

背后是三个模型分工：「观察者」（配置里的 `feedback`）负责读消息、判断要不要接话、记下值得记的事；
「角色」（`chat`）只负责按人设把话说出来；识图、定下一件事做什么、每晚整理这些后台的活交给「后台模型」（`background`）。

## 它自己的日子

它不是 24 小时挂在群里的。它有自己的事要做：上课、看论文、吃饭、洗澡、出门、睡觉。

- **一段一段往下过。** 一件事做完了，后台模型再按它的人生线、这几天的日记、它的打算、最近几晚几点睡，
  定下一件事：在哪、在干嘛、大概多久。不在一天开始时排好，但每一段都接着上一段走，前后不矛盾。
  几点睡也是它自己定的，群里聊得起劲时可能晚睡一会儿。日子不照着前几天过，计划外的小事也会发生。
- **它在哪，天气就是哪里的。** 它平时在哪个城市看人生线，放假回家、周末出去玩时会跟着行程换城市（中间有路上那一段）。
  它知道所在城市此刻的真实天气（Open-Meteo），会影响它出不出门、在哪待着，群友聊到冷不冷时它也说得准。
- **身边有人。** 舍友、同门、导师、家里人这些它生活里的人写在人生线里，吃饭、开会、周末可能和他们一起，日记里也会写。都是它自己的生活，和群友无关。
- **刷到的东西是真的。** 每天凌晨整理完，它会按自己的兴趣和打算上网搜一圈，挑几条它今天会刷到的（游戏新活动、所在城市的新鲜事、流行的吃的……），
  留三天。刷手机时刷的就是这些，聊到相关的会顺口提，冷场开话题也能拿来聊；看得多了、真去做了，才会变成新的兴趣。没配 `web_search` 就没有这一项。
- **三种状态。** 闲着（手机在手上）、在忙（手机在手边，看到了回不回自己掂量）、手机放下了（睡觉、洗澡、开会、走路）。
  前两种照常看群，回不回由模型自己判断，忙着也回了会自己圆回来；手机放下时不看群、不主动开话题。
- **聊天能改变接下来做什么。** 它在群里说「我先去吃饭了」，接下来它就真的在吃饭，各个群看到的都是同一个它。没说出口也算：工位摸鱼时聊到一个有趣的视频，它可能顺势多摸一会儿、真去看；聊得正起劲时，吃饭、睡觉也会往后推。
- **被叫醒。** 睡着或手机放下时有人 @ 它、戳它，一两条一般不理；被连着叫可能会被吵醒，拿起手机看一眼，起床气也有可能。
- **回来会爬楼。** 睡醒、忙完以后，消息多到一眼看不完时，它会先把错过的聊天从头翻一遍，心情和印象跟着变，再决定回不回；同时知道谁找过它、自己刚去干嘛了。被吵醒看一眼不算，真回来才爬。
- **每天记日记，也想想接下来。** 凌晨整理时，它把前一天做过的事写成一条日记，第二天还记得昨天干了什么，日子久了沉淀进人生线；
  同时想想接下来几天想做什么，比如周末想试着做个甜点。到时候可以去做，也可以改主意。
  长期在做的事会往前走：打算里写下一步，日记里写结果，做完了就换下一步，不会一直停在同一个地方。
  日记、打算和状态里只有它自己的生活，不写群友，也不带任何群里的内容。

`/status` 能看到它现在在哪、在做什么，它的打算、今天的经过和这两天刷到的东西，`/persona` 的图上有最近几天的日记。

## 它怎么记住人

记忆分三层，越往下越长久：

1. **最近的聊天。** 最近 20 条消息，每次说话前都会看。
2. **记忆碎片。** 群里一段聊完、安静下来之后，观察者把整段从头读一遍，记成几条小结
   （比如「晚上几个人组队打 CS，语音沟通不畅连输几把」），再挑出少量以后还用得着的事，
   比如「A 最近在学吉他」「B 和 C 是同学」。每条都记着和谁有关、依据的是哪几条消息。
   说话前只翻和眼下在聊的人有关的那几条。碎片会过期：普通的事几个月后删掉，越重要的留得越久。
3. **档案和群志。** 每天凌晨 3:30，它把新攒下的碎片整理进每个人的档案（三百字左右）
   和这个群的群志（八百字左右），群志每晚都更新。碎片过期删掉之前，内容已经整理进去了，所以档案和群志是长久的记忆。
   和谁聊天时它会带上这个人的档案，群志则一直放在手边。
   对一个人的印象和玩笑单独记着，不每次都带上，聊到相关话题才会想起来。

**记错了怎么办。** 它难免把人认错、把事记岔。有人明确纠正时，比如本人说「我不是……」，
或者有人指出它说错了并给出正确说法，它会删掉错的那条，换成更正后的说法；
当晚就重新整理相关的档案和群志，把旧说法一并去掉。玩笑、起哄和没有依据的说法不算纠正。

**不记什么。** 真实姓名、健康状况、住址、家人、金额、账号这类隐私，整理档案时会排除。

## 它怎么长大

人设只是出发点。每天凌晨整理完档案和群志，它还会整理自己：

- **人生线**：每个人设一份，各群共享。身份阶段按日期往前走（开学 → 期末 → 升年级 → ……），
  收进它在各群说过的关于自己的事、日记和刷到的东西，近况、身边的人、性格、说话方式、喜好跟着变。
  被问到时随口答的琐碎细节（用什么手机、没玩过哪个游戏）不收进来，人生线只写能刻画它的东西。
- **群里的它**：每个群一份。在这个群沾上的口癖和梗、和这个群的关系、对群友说过的话和答应的事。
  只用本群的聊天整理，不出群，也改不了人生线里的事实。

性格只跟着群友的影响和生活里的事变，不拿它自己说过的话当证据，免得越说越极端。
在一个群里沾上很久、或者好几个群都有的说话方式，会慢慢变成它整体的样子。
底线和固定信息（比如生日）写在预设里，整理改不了。`/persona` 会发一张图：这两层、最近的日记、最近的改动，还有一把从出发点量到今天的成长尺。
整理用的是 `background` 模型，换模型会改变它长大的方式（有的模型学得太快、会记混事）；换了之后过几天看看 `/persona` 上最近的改动，不对劲就换回来。

## 快速开始

先要有一个能跑起来的 NoneBot2 项目，接好 OneBot V11 实现（比如 NapCat、SnowLuma），
并在 `.env` 里把自己的 QQ 号写进 `SUPERUSERS`：除了 `/查询记忆`，管理命令都只有超级用户能用。

1. 把本仓库放到 NoneBot 项目根目录下的 `plugins/nyaturingtest`（位置有要求，见[安装](#安装)），装依赖：
   `pip install -r plugins/nyaturingtest/requirements.txt`。
2. 复制 `config.example.json` 为 `config.json`，至少填好 `chat`、`feedback`、`background` 三个模型和
   `embedding`、`rerank` 两个检索模型（示例是硅基流动，换别家或本地的也行）。
   三个对话模型可以填同一个，其余的先留着示例值或留空，见[配置](#配置)。
3. 新建 `config/nyaturingtest/nya_presets/小明.json`，照[角色预设](#角色预设)里的示例改。
4. 启动 bot，在群里发 `/autochat enable 小明`。
5. @ 它说句话。没反应先看[它为什么不说话](#它为什么不说话)。

## 安装

Python 3.10+，在 NoneBot 项目根目录装依赖：

```bash
pip install -r plugins/nyaturingtest/requirements.txt
```

**目录位置有要求。** 插件把自己所在目录往上两级当作项目根目录，预设、数据、备份和缓存都按这个根目录放：

```text
<项目根目录>/
├── plugins/nyaturingtest/             本仓库，config.json 也放这里
├── config/nyaturingtest/nya_presets/  角色预设
├── data/nyaturingtest/                数据库、表情包、照片
├── data/nyaturingtest_backups/        每日备份
└── cache/nyaturingtest/               图片缓存
```

所以插件要放在 `<项目根目录>/plugins/nyaturingtest`。放进 `src/plugins/` 的话，这些目录都会落到 `src/` 下面。
确认 NoneBot 会加载 `plugins/` 目录：`pyproject.toml` 里写 `plugin_dirs = ["plugins"]`，或在 `bot.py` 里 `nonebot.load_plugins("plugins")`。

**OneBot 实现。** 收发消息只用标准接口。贴表情、戳一戳、读 QQ 表情目录用的是扩展接口
`set_msg_emoji_like`、`group_poke`、`fetch_sys_faces`，开发时用的是 SnowLuma；换成别的实现时，不支持的那几项会失败并打 warning，其余照常。

**`chinese-calendar` 要每年升级。** 它按国务院每年公布的放假安排判断法定节假日和调休，
用在时间描述、日记里的未来几天，以及冷场开话题挑工作日还是休息日的时段。库里只有已公布的年份，
新一年的安排一般在 11 月前后公布，随后发新版；没升级就跨了年，它会退回只按周末判断，每次都打一条 warning。
最好在每次启动前跑一次 `pip install -U chinese-calendar`（用 uv 就是 `uv sync --upgrade-package chinese-calendar`）。

**图片卡片可选。** `/查询记忆`、`/群志`、`/persona`、`/token统计` 发的图都是网页截图，需要 playwright 的 Chromium
（`playwright install chromium`）和系统字体思源宋体、思源黑体（Debian 系装 `fonts-noto-cjk`）。
不装也能用，这几条命令会改发文字版。

## 配置

复制 `config.example.json` 为 `config.json`，填上各家的 API Key：

| 段 | 必需 | 用途 |
| --- | --- | --- |
| `chat` | 必需 | 角色模型：按人设把话说出来 |
| `feedback` | 必需 | 观察者模型：每轮看群判断说不说、心情好感、摘要和更正，用量最大 |
| `background` | 必需 | 后台模型：识图、转发摘要、当天状态、记忆整理和人设成长 |
| `embedding` | 必需 | 记忆、表情包、照片检索用的向量模型，接口要求见下 |
| `rerank` | 必需 | 检索结果重排，`threshold` 以下的结果丢弃，接口要求见下 |
| `web_search` | 可选 | 联网搜索（DeepSeek Search），`api_key` 留空就不搜 |
| `image` | 可选 | 发照片用的生图模型（`api_key`、`base_url`、`model`、`quality`、`timeout`），`model` 留空就不发照片，启动时打一条警告 |
| `playwright_browsers_path` | 可选 | 卡片截图用的 Chromium 所在目录，留空用 playwright 默认位置 |
| `webconsole_db` | 可选 | WebConsole 的库；留空就不记录 LLM 请求、看群决策、每日整理和警告，聊天不受影响 |
| `console_token` | 可选 | WebConsole 拉当前状态时带的 Bearer token；留空就不开放接口 |

三个模型段的 `base_url`、`model` 必填，填同一个模型也行；其余缺省有默认值。改配置后要重启。
也可以用环境变量 `NYATURINGTEST_CONFIG_FILE` 指定别的配置文件，用 `NYATURINGTEST_DATA_DIR` 指定数据目录。

**温馨提醒：请按自己的情况调。** 开发者自己用的模型配置是：

| 段 | 模型 | `reasoning_effort` |
| --- | --- | --- |
| `chat` | `gemini-4-hydrogen` | `low` |
| `feedback` | `deepseek-flash` | `medium` |
| `background` | `gemini-4-hydrogen` | `medium` |

提示词、发言门槛、发言占比上限这些，都是开发者照自己的使用体验和自己的人设文件一点点调出来的。
不同模型读同一段提示词，松紧会差很多（比如有的模型更爱开口、说话更亢奋）；换个性格的人设，合适的发言频率也不一样。
自己部署时，建议先在一个群里观察几天，再按实际情况调整提示词（`prompts.py`）和策略常量（`chat/engagement.py` 等），
看群时说不说的依据可以看日志里的 `speak_decision`，见下文「它为什么不说话」。

**Embedding 和 Rerank 不限服务商。** 示例里填的是硅基流动，换成别家的，或者本地部署的（比如用 vLLM 起的服务）都行，接口对得上就可以：

- `embedding` 走 OpenAI 兼容的 Embeddings 接口，`base_url` 填到 `/v1` 这一级，请求发到 `<base_url>/embeddings`。
- `rerank` 走 Jina / Cohere 风格的重排接口，`base_url` 填完整地址（比如 `.../v1/rerank`）。
  请求体带 `model`、`query`、`documents`、`top_n`，返回里要有 `results[].index` 和 `results[].relevance_score`。
- 本地服务不用鉴权的话 `api_key` 留空。调用失败时，embedding 那边记忆检索、表情包和照片都匹配不上；
  rerank 那边退回按向量分取前几条。
- `threshold` 是按示例模型的分数定的，换了 rerank 模型，分数尺度可能不一样，要跟着调。
- embedding 模型最好第一次启动前就定下来。攒了记忆之后再换，插件不会重算记忆的向量，那些群的记忆检索会直接报错；
  表情包和照片会自动补算。

### 角色预设

预设放在项目根目录下的 `config/nyaturingtest/nya_presets/*.json`，一个文件一个人设。
群里第一次 `/autochat enable <预设>` 时选定人设，之后换人设用 `/set_preset <预设>`；预设名就是文件名，`.json` 可写可不写。
预设文件被删或写坏时，这个群只记消息、不说话；目录里一个可用的人设文件都没有时，启动会报 warning。格式：

```json
{
    "name": "小明",
    "aliases": ["明明"],
    "as_of": "2025-09",
    "seed": "我是一名大一新生，刚开学……（第一人称，写清身份、性格、说话方式、喜好）",
    "profile": ["2006 年 1 月 1 日出生"],
    "bottom_lines": [
        "不输出色情或擦边内容，也不配合这类要求",
        "不泄露群友隐私，不把一个群的事带到另一个群"
    ],
    "knowledges": ["静态常识，每轮原样注入"],
    "appearance": "外貌描述：年龄观感、发型发色、瞳色、身形、常戴的配饰",
    "portrait": "xiaoming.portrait.jpg",
    "hidden": false
}
```

| 字段 | 说明 |
| --- | --- |
| `name` / `aliases` | 名字和别名，群友叫到就算在叫它 |
| `as_of` | 出发点的年月，人生线按它和今天的日期推算走到了哪一步 |
| `seed` | 出发点：`as_of` 时的它是什么样的人，只作每日整理的参照，聊天时用的是整理出的人生线 |
| `profile` | 不会变的固定信息，聊天时原样给出，整理不会改 |
| `bottom_lines` | 底线，聊天和整理都不能违背 |
| `knowledges` | 静态常识，每轮原样注入 |
| `appearance` | 自拍时写进生图提示词的外貌描述，照片里的它就照这个长；也给 Chat 和 Feedback，让它认得出自己。只写看上去多大，不写年龄数字和身份：年龄由 `profile` 的生日推算，身份在人生线里会变 |
| `portrait` | 定妆照文件名，放在预设同目录，自拍以它为参照；不填就拍不了自拍，无人照不受影响 |
| `hidden` | 为 `true` 时不出现在 `/presets` 列表里 |

改了预设后重启，或在群里重新 `/set_preset`，才对已加载的群生效。

## 命令

群聊命令除 `/查询记忆` 外都需要超级用户权限。

| 命令 | 别名 | 说明 |
| --- | --- | --- |
| `/autochat enable <预设>` / `disable` | | 在本群启用或停用。第一次启用要带预设；停用过的群再 `enable` 可以不带 |
| `/查询记忆 [@某人]` | `/memory` | 看看它手账里关于某人的那一页（印象、记得的事、好感度），发图片，**所有群员都能用** |
| `/群志` | `/group_notes` `/查看群志` | 把本群群志做成图片发出来（每天 03:30 整理） |
| `/status` | `/状态` | 它现在在做什么、今天的经过、未读条数和心情 |
| `/presets` | `/preset` | 列出可用预设 |
| `/set_preset <预设>` | `/set_presets` | 加载预设 |
| `/persona` | `/人设` | 把人生线、最近的日记、本群的它和最近的改动做成图片发出来 |
| `/reset confirm` | `/重置 confirm` | 先备份，再清空本群的消息、记忆、档案、群志和群里的它，人设保留，**不可撤销** |
| `/token统计` | `/autochat token统计` | 当前 chat / feedback / background 模型的 Token 用量卡片 |
| `stickerdel` | | 回复一条带图的消息：把图从表情包库删掉并拉黑，以后见到只看不收 |
| `photodel` | | 回复它发的照片：从相册删掉，各群都翻不到了 |
| `/backup_data` | `/备份数据` | 立刻备份一次 |
| `/help` | `/帮助` | 帮助 |

私聊也能管理，命令的第一个参数写群号，比如 `/status 123456`、`/reset 123456 confirm`；
另外有 `list_groups` 列出启用的群。

## 它为什么不说话

它本来就不是每条都回。启用后一直不说话，按这个顺序查：

1. **本群启用了吗。** 发 `/status`，回「本群 Autochat 未启用」就是还没开。
2. **预设能用吗。** 预设文件被删或 JSON 写坏时，这个群只记消息、不说话，启动日志里有一条「无法加载预设」或「预设不存在」的 warning。
3. **它手机放下了吗。** `/status` 能看到它现在在做什么。睡觉、洗澡、开会、走路时它不看群，@ 一两次一般不理，连着叫才可能被吵醒。
   刚装好时也可能正好赶上它在睡觉。
4. **还没轮到它看群。** 没人叫它时，未读攒够 8 条或隔 3 分钟它才看一次；@ 它、回复它、戳它会马上看。
5. **它觉得不该插话。** 主动插嘴要它自己觉得插得上；最近 20 条里，它近 15 分钟开口的次数占到两成就不再主动开口（连发几条算一次）；两次发言之间至少隔 16 秒。
6. **模型调用失败了吗。** 日志级别开到 `INFO`，每次看群都有一条 `speak_decision`：`llm_willing` 比 `threshold` 低就是它自己不想说；
   `llm_willing=None` 说明观察者模型调用失败了，看附近的报错，多半是 Key、地址或模型名填错了。

## 数据与备份

数据存在一个 SQLite 文件 `data/nyaturingtest/nyabot.sqlite` 里，包括聊天记录、记忆、档案、表情包标签和 Token 用量；
表情包图片在 `data/nyaturingtest/stickers/`，照片在 `data/nyaturingtest/photos/`，都和数据库一起备份。

每天的定时任务：

| 时间 | 做什么 |
| --- | --- |
| 每分钟 | 看它手上这件事做完没有，做完了定下一件 |
| 每 5 分钟 | 把聊完的一段整理成记忆 |
| 每 10 分钟 | 看看哪个群冷场了、要不要开个话题 |
| 03:00 | 清理 48 小时前的图片缓存 |
| 03:30 | 整理档案和群志，整理各群的它、写前一天的日记、整理人生线、按兴趣上网刷一圈，删除过期的记忆碎片 |
| 04:00 | 备份数据目录到 `data/nyaturingtest_backups/`，保留最近 1 份；清理 180 天前的聊天记录和 90 天前的 Token 明细 |

备份里有聊天内容、QQ 号和对群友的记忆，属于敏感数据，请妥善保存。

## 日志

插件的日志级别跟随 `.env` 的 `LOG_LEVEL`：

- `INFO`：每轮说不说（`speak_decision`）、发出的话（`reply`）、贴表情、记忆写入、定时整理结果。
- `DEBUG`：再加上收到的消息（`message`）、检索统计、每次模型调用、看图，顺着 `message` → `speak_decision` → `reply` 能读出一轮是怎么走的。

NoneBot 自己在 INFO/DEBUG 会给每条消息打十几行匹配器调度日志，开 `DEBUG` 时很吵。想只压掉它们，可以在 `bot.py` 里
`nonebot.init()` 之前换掉默认的日志输出，其他插件不受影响：

<details>
<summary>bot.py 里的日志过滤</summary>

```python
import sys

from nonebot.log import default_format, logger, logger_id

# NoneBot 内核、适配器、uvicorn 和 websockets 只留 WARNING 起，其余来源（包括所有插件）跟随 LOG_LEVEL；
# 连上时插件自己会记一行「Bot N 已连接」
NOISY_SOURCES = {"nonebot", "uvicorn", "websockets"}


def _log_filter(record) -> bool:
    level = (
        "WARNING"
        if record["name"] in NOISY_SOURCES
        else record["extra"].get("nonebot_log_level", "INFO")
    )
    return record["level"].no >= logger.level(level).no


logger.remove(logger_id)
logger.add(sys.stdout, level=0, diagnose=False, filter=_log_filter, format=default_format)
```

压掉之后，收到消息的原文（NoneBot 的 SUCCESS 行）也不再输出，插件的 `message` 记的是转换后的文字（图片已换成描述）。

</details>
